# Building GlyphLink

These instructions are for developers. End users only need the complete setup EXE.

## Project map

| Path | Contents |
| --- | --- |
| pc/ | Windows desktop app, audio capture, pattern editor and images |
| android/app/src/main/ | Android UI, background service, boot receiver and Glyph adapter interface |
| installer/ | Setup UI, phone checks, controller, integrity validation and NSIS launchers |
| scripts/ | Payload validation and offline Android build |
| tests/ | Installer, controller and GUI checks |
| release/ | Dependencies, notes and validation results |

## Android companion

Open android/ in Android Studio with JDK 17, Android SDK platform 35 and build-tools 35.0.0. This project uses Android Gradle Plugin 8.9.1 and Kotlin 2.0.21. Use a local Gradle 8.11.1 installation; a Gradle wrapper is not included. Development builds can use `gradle assembleDebug` from android/.

Use Android Studio's **Generate Signed Bundle / APK** for a signed release. Release builds are unsigned until you supply a signing configuration.

The alternate offline route used for the included APK is `python scripts/build_android_offline.py`. Set ANDROID_HOME, JAVA_HOME and KOTLIN_LIB_DIR first. The script expects Linux SDK tool filenames, JDK 17 and Kotlin 2.0.20 compiler jars, including kotlin-stdlib-2.0.20.jar and annotations-24.0.1.jar. Its output is installer/payload/android/GlyphLink.apk.

Signing secrets are excluded from the repository. The offline script creates a new key if none exists. Adam's original release key is backed up separately: restore the complete signing/ folder before building compatible official Android updates. A new key cannot update the existing Android release in place.

## Windows app and installer

For development, install pc/requirements.txt in 64-bit Python 3.12 on Windows, make Android platform-tools available, and run `python pc/glyphlink.py`.

Prepare installer/payload/ with this structure:

- app/glyphlink.py: copy current pc/glyphlink.py.
- app/assets/: copy pc/assets/.
- app/GLYPHLINK-LICENSE.txt and app/THIRD_PARTY_NOTICES.md: copy the repository license and third-party notices.
- app/runtime/: complete CPython 3.12.10 x64 runtime, including Python DLLs, Visual C++ runtime DLLs, Lib/, DLLs/ and tcl/.
- app/runtime/Lib/site-packages/: Windows wheels listed in release/dependencies.txt, retaining license and dist-info files.
- platform-tools/: Google's Windows platform-tools, including adb.exe, both ADB DLLs and supplied notices.
- android/GlyphLink.apk: the signed companion APK.

The released runtime was assembled from Python.org's core.msi, exe.msi, lib.msi and tcltk.msi at [the official CPython distribution](https://www.python.org/ftp/python/3.12.10/amd64/). Python's embeddable ZIP alone lacks the required Tcl/Tk files. The validator checks required runtime files and refuses generated bytecode in release payloads.

With NSIS 3.09 or later installed, run in this order:

```text
cd installer
makensis launcher.nsi
cd ..
python -B scripts/prepare_manifest.py
cd installer
makensis setup.nsi
```

Output: release/GlyphLinkSetup-1.3.6.exe. Both launchers must retain the Python flags `-B -E -s`. Validate the actual extracted payload and test on Windows with the supported phone before publishing further releases.

## Tests

```text
python -B -m unittest discover -s tests -v
python -B tests/check_setup_ui.py build/ui-check
```

GUI checks require CustomTkinter, Pillow and a running display. They use simulated phone events and never execute ADB or install apps.

## GitHub

Extract the source ZIP and upload the contents of its GlyphLink-1.3.6 folder to the repository. Keep the license, README, notices and source folders. Create a release tagged v1.3.6 and attach GlyphLinkSetup-1.3.6.exe as a release asset.

The source archive intentionally excludes compiled EXEs, APKs, the downloaded runtime, temporary builds and signing secrets.
